# 代码评审清单（Code Review Checklist）

> 用于 PR 审查，优先检查正确性与风险，再看风格。

## 1. 正确性（Correctness）

- [ ] 代码实现与需求一致（无漏实现、无错实现）。
- [ ] 关键边界条件已覆盖（空值、重复提交、非法状态）。
- [ ] 错误处理清晰（异常、返回码、错误信息一致）。

## 2. 架构与设计（Design）

- [ ] 分层合理：`controller` 仅处理协议，业务逻辑在 `service`。
- [ ] 无明显重复逻辑，可复用代码已抽象。
- [ ] 对外接口兼容性已评估（字段、语义、默认值）。

## 3. 数据与事务（Data & Transaction）

- [ ] SQL/ORM 操作安全且高效（索引、分页、N+1 风险）。
- [ ] 事务边界明确，避免跨层隐式事务。
- [ ] 幂等性处理合理（重试/超时/重复请求场景）。

## 4. 安全性（Security）

- [ ] 鉴权/授权检查完整，不存在越权路径。
- [ ] 输入参数有校验与过滤，避免注入与反序列化风险。
- [ ] 敏感信息不写入日志（手机号、token、密码等）。

## 5. 可观测性（Observability）

- [ ] 关键路径有结构化日志，能定位问题。
- [ ] 错误日志包含上下文（traceId、业务主键）。
- [ ] 必要指标与告警策略已补充（失败率、耗时、异常数）。

## 6. 测试（Testing）

- [ ] 新增/修改逻辑有对应测试（单测或集成测试）。
- [ ] 测试覆盖主流程 + 异常流程 + 权限场景。
- [ ] 本地或 CI 已验证通过。

## 7. 变更风险（Release Risk）

- [ ] 数据库变更可回滚（DDL/DML 有脚本与说明）。
- [ ] 配置变更有默认值，且与环境兼容。
- [ ] 灰度/回滚方案明确。

## 8. PR 质量（PR Hygiene）

- [ ] PR 规模可审阅（建议 200-400 行核心变更）。
- [ ] 描述完整（目标、方案、风险、测试、回滚）。
- [ ] Commit 信息清晰（建议遵循 Conventional Commits）。
