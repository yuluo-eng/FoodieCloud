# 项目测试方案（黑盒 · 白盒）

本文档与 [`development-documentation.md`](./development-documentation.md)、[`checklist.md`](./checklist.md) 对照使用：前者定义**测什么**，本文定义**怎么测**以及**如何判定代码侧健壮性**。测试环境准备见 [`deploy-guide.md`](./deploy-guide.md)。

---

## 1. 测试目的与范围

| 类型 | 目的 | 主要依据 |
|------|------|-----------|
| **黑盒测试** | 验证四类前端功能与客户可见行为是否符合需求 | `checklist.md`、本文第 2 节 |
| **白盒测试** | 验证后端逻辑、边界、并发与安全属性是否成立 | `src/test/java/**`、本文第 3 节 |

**不在本文范围**：性能压测、安全渗透（可作为后续专项）；生产监控与告警。

---

## 2. 黑盒测试（前端功能鉴定）

黑盒测试从**用户可操作路径**出发，不依赖实现细节。建议每次发版前至少执行「冒烟子集」（标 ★）一次，全量对照 `checklist.md` 勾选。

### 2.1 用户端

| 编号 | 场景 | 关键操作与预期 | 与文档对应 |
|------|------|----------------|------------|
| UB-01 ★ | 注册登录 | 注册成功跳转登录；登录成功进入 `/user`；刷新保持登录 | checklist 1.1 |
| UB-02 ★ | 店铺列表 | `/user` 展示营业中店铺；点击进入 `/user/shop/:shopId` | development-documentation §3 |
| UB-03 ★ | 点餐 | 分类与菜品加载正确；仅展示上架菜品；购物车角标与增减 | checklist 1.3 |
| UB-04 ★ | 下单支付链路 | 购物车勾选 → 订单确认（含 `shopId`）→ 支付页 → 模拟支付成功 → 结果页可返回 | 下单流程增强 |
| UB-05 | 订单与配送信息 | 订单列表展示状态；配送中展示骑手信息（若有） | 三端联动 |
| UB-06 | 个人资料与上传 | 资料修改成功；头像上传符合大小与类型限制 | checklist 1.2 |
| UB-07 | 异常与体验 | 非法路径进 404；断网/超时 Toast 文案正确 | checklist 4、6 |

**记录**：执行人、日期、浏览器、通过/失败、截图或备注。

## 3. 白盒测试（后端与代码健壮性）

白盒测试关注**代码路径、边界条件、异常与安全属性**。本项目已有自动化测试为基线，发布前执行 `./mvnw test`。

### 3.1 单元测试（JUnit + Mockito）

| 关注点 | 说明 | 典型位置 |
|--------|------|-----------|
| 订单服务 | 商家接单、店铺不匹配、状态机 | `OrderServiceImplTest` |
| 支付与库存 | 支付成功扣库存、库存不足异常 | `PaymentServiceImplTest` |
| 骑手履约与商家自配冲突 | 路由到正确分支与错误码 | `RiderOrderFulfillmentServiceTest` |
| 商家鉴权 | Token 解析与角色 | `MerchantAuthGuardTest` |

**健壮性要求**：新增业务分支应同步补充或更新对应测试类；Mock 构造须与当前构造器依赖一致。

---

### 3.2 集成 / 关键路径测试

| 测试类 | 覆盖内容 |
|--------|-----------|
| `OrderFlowIntegrationTest` | 无骑手参与的下单→支付→商家全流程；库存不足回滚 |

**说明**：集成测试依赖数据库与 Spring 上下文配置，CI 中需保证环境一致（见 `deploy-guide.md`）。

---

### 3.3 安全与并发（白盒审查清单）

| 项 | 验证方式 |
|----|-----------|
| 店铺隔离 | 商家接口传参 `shopId` 与 JWT 解析出的员工 `shopId` 一致；单测与接口测试覆盖跨店 |
| 库存并发 | SQL 条件更新 + 事务；`PaymentServiceImplTest` 中断言扣减失败路径 |
| JWT 与角色 | 管理接口仅 `SUPER_ADMIN`；代码审查 `MerchantAuthGuard` / Controller |
| 上传 | Controller 中大小与 MIME 校验不可绕过 |

---

### 3.4 前端静态与构建（建议门禁）

| 项 | 命令 / 说明 |
|----|-------------|
| 前端构建 | `npm run build`（根目录 `frontend`）无错误 |
| 路由完整性 | 新增页面注册路由；404 兜底存在 |
| ESLint（若已配置） | `npm run lint` |

### 7.2 主链路用例

#### TC-001 用户注册 → 登录 → 选店 → 点餐 → 下单

| 步骤 | 操作 | 预期结果 | 通过 |
|------|------|---------|------|
| 1 | 打开 `/user/register`，填写表单提交 | 注册成功，跳转登录页 | |
| 2 | 登录后进入 `/user` 店铺列表，点选某店 | 进入 `/user/shop/:shopId` | |
| 3 | 选择分类，添加菜品到购物车 | 购物车角标更新 | |
| 4 | 打开购物车，修改数量，点击结算 | 进入订单确认 / 支付相关页，下单成功，购物车按业务清空 | |

#### TC-002 支付 → 库存扣减

| 步骤 | 操作 | 预期结果 | 通过 |

#### TC-004 骑手接单 → 履约

| 步骤 | 操作 | 预期结果 | 通过 |

### 7.3 异常链路用例

| 编号 | 场景 | 操作 | 预期 |
|------|------|------|------|
| TC-101 | 库存不足 | 菜品 stock=0 时模拟支付 | 返回业务错误，提示库存不足，支付与订单状态不变 |
| TC-102 | 跨店铺操作 | 商家 A 员工操作商家 B 订单 | 403 或业务拒绝 |
| TC-103 | Token 失效 | 过期 Token 请求 | 401，前端跳转登录 |
| TC-104 | 上传非法文件 | .exe 或超大图片 | 提示类型或大小错误 |
| TC-105 | 重复支付 | 对已支付订单再次 mockSuccess | 幂等，不重复扣库存 |
| TC-106 | 404 | 访问不存在路由 | 前端 404 页 |
