# 悦食汇项目学习路线（功能复现驱动 + 测试训练）

本文档改为“按功能逐个复现”的后端学习路线，默认你已具备三层架构基础，不再重复泛化讲解，直接聚焦 Java 后端实现能力提升。

---

## 1. 学习目标（按优先级）

- 能独立复现核心功能：认证、购物车、下单、支付、履约
- 能给每个功能补“成功 + 边界 + 异常”测试
- 能在不看答案情况下完成小功能改造并通过回归
- 形成功能级复盘文档，支持后续快速维护和扩展

---

## 2. 功能复现统一方法（每个功能都按这 5 步）

1. **选定功能范围**：只看一个业务闭环，不扩散
2. **定位最小代码集**：`controller + service + mapper + xml + test`
3. **手写复现（小步）**：先主流程，再异常分支
4. **补测试闭环**：至少 3 类（正常、非法参数/状态、权限/并发）
5. **写复盘卡片**：输入、输出、关键 SQL 条件、易错点

## 5. 关于“在测试类里写实现”的建议

你的思路很好，但建议做一个边界区分：

- 可以在测试中做“实验性实现（Spike）”来验证想法
- 不建议把正式业务实现长期放在 `src/test/java`，会导致生产代码不可维护

推荐做法：

1. 在测试先写失败用例（红灯）
2. 在 `src/main/java` 写最小实现让测试通过（绿灯）
3. 回到测试补边界，再重构（重构）

如果你确实要做“测试中原型验证”，请遵守两条：

- 原型类命名为 `*Prototype` 或 `*Spike`，并加 `@Disabled` 或明确注释
- 一旦方案成立，24 小时内迁移到 `src/main/java`，并删除原型代码

## 7. 自测完成标准（功能复现达标）

- 不看旧代码，能独立写出一个功能的最小可用实现
- 能独立补齐该功能 3 类测试（正常、异常、权限/并发）
- 能用日志和断点在 30 分钟内定位主要问题层级
- 能写出该功能 10 行内复盘（输入、输出、状态、风险）
