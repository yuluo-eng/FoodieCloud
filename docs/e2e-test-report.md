# MVP 端到端回归用例与测试报告

## 测试环境

| 项目 | 说明 |
|------|------|
| 后端 | Spring Boot 3.x + MyBatis + MySQL 8 |
| 前端 | Vue 3 + Vite |
| 浏览器 | Chrome / Safari (iOS) |
| 测试方式 | 手动 + 单元测试 (JUnit 5 + Mockito) |

---

## 主链路用例

### TC-001 用户注册 → 登录 → 点餐 → 下单

| 步骤 | 操作 | 预期结果 | 通过 |
|------|------|---------|------|
| 1 | 打开 `/user/register`，填写表单提交 | 注册成功，跳转登录页 | |
| 2 | 输入刚注册的账号密码登录 | 跳转用户首页 | |
| 3 | 选择分类，添加菜品到购物车 | 购物车角标更新 | |
| 4 | 打开购物车，修改数量，点击结算 | 下单成功 Toast，购物车清空 | |

### TC-002 支付 → 库存扣减

| 步骤 | 操作 | 预期结果 | 通过 |
|------|------|---------|------|
| 1 | 在订单列表创建支付单 | 支付单号 Toast | |
| 2 | 点击"模拟支付成功" | 订单变为"已支付"，菜品 stock 减少 | |
| 3 | 查询支付状态 | 显示"已支付" | |

### TC-003 商家订单处理

| 步骤 | 操作 | 预期结果 | 通过 |
|------|------|---------|------|
| 1 | 商家登录，查看订单列表 | 显示待处理订单 | |
| 2 | 接单 | 订单状态→已接单 | |
| 3 | 发起配送 | 订单状态→配送中 | |
| 4 | 完成订单 | 订单状态→已完成 | |

### TC-004 骑手接单 → 履约

| 步骤 | 操作 | 预期结果 | 通过 |
|------|------|---------|------|
| 1 | 骑手登录，查看可接订单 | 列表显示已支付订单 | |
| 2 | 接单 | 订单移到"进行中" | |
| 3 | 依次：到店 → 取餐 → 送达 | 按钮依次变化，最终订单消失 | |
| 4 | 查看历史记录 | 显示已完成订单 | |

## 异常链路用例

### TC-101 库存不足

| 操作 | 预期结果 |
|------|---------|
| 菜品 stock=0 时模拟支付 | 返回 400，提示"库存不足"，支付和订单状态不变 |

### TC-102 跨店铺操作

| 操作 | 预期结果 |
|------|---------|
| 商家 A 员工尝试接商家 B 的订单 | 返回 403 |

### TC-103 Token 过期

| 操作 | 预期结果 |
|------|---------|
| 使用过期 Token 请求接口 | 返回 401，前端自动跳转登录页 |

### TC-104 上传非法文件

| 操作 | 预期结果 |
|------|---------|
| 上传 .exe 文件 | 提示文件类型不支持 |
| 上传 > 5MB 图片 | 提示文件过大 |

### TC-105 重复支付

| 操作 | 预期结果 |
|------|---------|
| 对已支付订单再次调用 mockSuccess | 幂等处理，不重复扣款 |

### TC-106 404 页面

| 操作 | 预期结果 |
|------|---------|
| 访问不存在的路径 `/abc123` | 显示 404 页面，可返回首页 |

## 结论

主链路 4 条 + 异常链路 6 条均已设计用例。单元测试覆盖核心 Service 层（订单、支付、鉴权、骑手履约），Mock 层面验证了业务逻辑正确性。
